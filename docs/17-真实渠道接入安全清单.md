# 真实渠道接入安全清单（17）

> 状态：未开始（当前支付为纯 MOCK 渠道、本地使用；本清单为接入微信/支付宝前的检查依据）

## 背景与威胁模型转变

当前支付链路（M5.2）为纯 MOCK 渠道：验签、幂等、金额校验、状态机守卫、事务入账均已在本地联调验证。接入真实渠道（微信支付 / 支付宝）后，威胁模型发生两个变化：

1. **问题性质从「安全」升级为「资损」**：回调丢失、超时关单不一致等不再只是体验问题，而是真金白银的损失。
2. **攻击面从本机变为公网**：回调端点 `@Public` 暴露公网，`PAY_MOCK_SECRET` 默认值、mock-pay 入口等「本地无威胁」的债务全部激活为可利用漏洞。

因此接入真实渠道前，必须按本清单逐项核对。分类说明：

- **A 资损类**：会导致用户付款但未获得会员，或会员计算错误；
- **B 漏洞类**：会导致免费开通会员或越权入账；
- **C 实现坑**：编写渠道适配器时的高频错误点。

## A. 资损类（必须优先处理）

### A1. 回调丢失无补偿机制 ⚠️ 最优先

- **现状**：会员生效完全依赖渠道异步回调这一条腿（`PayService.handleNotify`）。回调丢失（网络抖动、服务重启、渠道故障）时订单永远 PENDING，用户付款但无会员。
- **位置**：`backend/src/modules/member/pay/pay.service.ts`（当前无任何主动查单/对账逻辑）。
- **修复**：
  - [ ] 前端支付后轮询查单（已有 `GET /member/orders/:orderNo`，需确认轮询至终态才停）；
  - [ ] 服务端定时任务主动查单：扫描超过 N 分钟仍 PENDING 的订单，调渠道查单 API，若渠道侧已支付则补入账（走与回调相同的入账路径，注意幂等）；
  - [ ] 每日对账：拉渠道对账单与本地 `paymentRecord` 比对，差异告警。

### A2. 超时关单与渠道侧不一致

- **现状**：订单 30 分钟支付有效期，但仅在下次发起支付时**懒关闭**（`OrderService.pay` 中置 CLOSED），从未调用渠道关单 API。用户扫码后第 31 分钟付款成功 → 回调到达 → 订单已 CLOSED → 走 FAILED 流水不入账 → **钱付了没会员**。
- **位置**：`backend/src/modules/member/order.service.ts`（`pay` 的懒关闭逻辑）、`backend/src/modules/member/pay/pay.service.ts`（`ORDER_NOT_PENDING` 分支只记 FAILED）。
- **修复**：
  - [ ] 关单时同步调用渠道关单 API（微信 closeOrder），阻止用户继续支付已过期订单；
  - [ ] 定时任务批量关闭超时 PENDING 订单并同步渠道关单（替代懒关闭）；
  - [ ] 已 CLOSED/非 PENDING 订单收到成功回调时，走退款或人工对账路径，而非仅记 FAILED 流水。

### A3. 会员区间并发竞态

- **现状**：回调入账链路中「读当前订阅 → 计算生效区间 → upsert 订阅」三步中，读订阅发生在**事务外**。用户并发支付两单（双端同时扫码）时，两笔均基于同一旧到期日计算，后写覆盖先写 → 丢一期会员。
- **位置**：`backend/src/modules/member/pay/pay.service.ts`（`getSubscriptionSystem` 与 `settlePayment` 的 `upsert` 不在同一事务且无锁）。
- **修复**：
  - [ ] 将订阅行读取加悲观锁（`SELECT ... FOR UPDATE`，Prisma 用 `$queryRaw`）；
  - [ ] 或将区间计算整体移入 `settlePayment` 事务内，配合行锁串行化。

### A4. 退款链路缺失

- **现状**：`OrderStatus` 定义了 `REFUNDED`，但无线上退款实现：无法发起退款，退款后会员不回收。
- **位置**：`backend/src/modules/member/order.service.ts`（状态机定义）、`pay-channel.ts`（适配器接口无退款方法）。
- **修复**（可上线后第二批做）：
  - [ ] 适配器接口扩展退款方法（微信退款 API / 支付宝退款）；
  - [ ] 退款成功后会员回收策略（立即失效 or 保留至期末，需产品决策）；
  - [ ] 退款与回调同样需要幂等与验签。

## B. 漏洞类（接渠道 = 上生产，本地 P0 债务激活）

### B1. MOCK 渠道退役三件套

- **现状**：`MockPayChannel` 无条件注册；`POST /member/orders/:orderNo/mock-pay` 无环境开关；`PAY_MOCK_SECRET` 未配置时仅 warn 放行。生产上任一漏掉 = 知道源码/默认密钥的人可伪造回调免费开会员。
- **位置**：`backend/src/modules/member/member.module.ts`（注册表）、`backend/src/modules/member/order.controller.ts`（mock-pay 入口）、`backend/src/modules/member/pay/mock.channel.ts`（secret 默认值）。
- **修复**：
  - [ ] MOCK 适配器按环境注册（生产环境不注册进 `PayChannelRegistry`）；
  - [ ] mock-pay 入口按环境关闭（非 dev 返回 404），或限制为测试账号；
  - [ ] `PAY_MOCK_SECRET` 为默认值时生产环境拒绝启动（fail-fast）。

### B2. 回调渠道与订单渠道不校验

- **现状**：`handleNotify` 用 URL 上的 channel 选适配器验签，但未校验 `order.channel` 与回调渠道一致，存在跨渠道入账风险（如 MOCK 渠道给 WECHAT 订单入账）。
- **位置**：`backend/src/modules/member/pay/pay.service.ts`（渠道选择与订单查询之间）。
- **修复**：
  - [ ] 取到订单后校验 `order.channel === normalized`，不一致记 FAILED 流水并返回失败。

### B3. 支付审计落库缺失

- **现状**：支付操作（入账、拦截、金额不符）仅运行日志（`logger.log/warn`），无审计表，纠纷时无法追溯。
- **位置**：全支付链路。
- **修复**：
  - [ ] 新增审计日志表（或复用规划的 `audit_log`），记录：操作类型、订单号、流水号、渠道、金额、结果、原始报文摘要、时间；
  - [ ] 与提示词注入防护的「审计落库」未做项（见 docs/16）共用同一张审计表设计。

## C. 实现层的坑（编写适配器时对照）

| # | 坑 | 说明与对策 |
|---|---|---|
| C1 | 证书/密钥管理 | 微信 APIv3 平台证书**会轮换**，需定时拉取新证书，否则某天验签全挂；支付宝验签必须用**支付宝公钥**（不是应用公钥） |
| C2 | 金额单位 | 支付宝部分接口金额为**元（字符串）**，微信为分；适配器转 `amountCents` 时统一为分，注意浮点精度（用字符串解析而非 parseFloat） |
| C3 | 并发同 txn 回调 | 两笔并发同流水号回调同时过 `findPaymentByTxn` 前置查，后落库者撞 `paymentRecord` 唯一约束抛 500；catch Prisma P2002 后转幂等成功返回 |
| C4 | FAILED 流水幂等短路 | 金额不符的回调重试会命中已存在的 FAILED 流水返回 `ok:true`，渠道停止重试，系统性 bug 被掩盖；建议幂等短路仅对 SUCCESS 流水生效 |
| C5 | 续费单渠道硬编码 | `OrderService.renewIfNeeded` 中懒续费订单写死 `channel: 'MOCK'`；MOCK 摘除后懒续费直接报错，须改为用户原支付渠道（订单快照或订阅记录里取） |
| C6 | 同单重复预支付 | 同一 orderNo 多次 `createPrepay`：微信要求同单号金额一致否则报错（当前金额来自下单快照，逻辑已满足，接入后必须实测）；前端收银台需处理「旧码仍在有效期」的展示 |

## 建议接入顺序

架构本身（适配器模式、验签、幂等、状态机、事务入账）无需大动，按以下顺序补强：

```
A1 主动查单/对账 → A2 渠道关单 → B1 MOCK 退役 → A3 订阅行锁
→ B2 渠道一致性校验 → C 类各坑随适配器开发逐项验证
→（上线后第二批）A4 退款、B3 审计落库
```

## 验证要求

接入后回归项：

- [ ] 回调验签：篡改签名/篡改金额/过期时间戳均被拒（对齐 `mock.channel.ts` 现有用例思路）；
- [ ] 幂等：同流水号重复回调、并发回调均只入账一次；
- [ ] 状态机：CANCELLED/CLOSED/PAID 订单收到回调不重复入账；
- [ ] 主动查单补偿：模拟回调丢失后查单任务补入账；
- [ ] 超时关单：订单关闭后渠道侧无法再支付；
- [ ] MOCK 退役：生产环境注册表无 MOCK、mock-pay 404、默认 secret 拒绝启动。
