## 一、总体架构：两段式请求

原单条 SSE 走完全程（检索→生成），重构为两条接口：

```
第一段（检索）                    第二段（生成）
POST /search/stream               POST /search/stream/generate
  stage(intent)                    入参: { sessionId, selectedIdxs }
  cond_fill                         stage(generating)
  stage(searching)                  report_chunk × N
  source × N（全部候选）            stage(done)
  stage(fusing)                     done { sessionId, reportId }
  sources_ready { sessionId }  ←    （仅勾选来源参与生成）
  SSE 正常结束，等待用户选择
```

**为什么不用「SSE 挂起等用户确认」**：SSE 单向通信，等用户需换 WebSocket/轮询；长连接空挂易被网关掐（心跳只是缓解）；两段式下检索结果落库持久化，刷新/离开天然可恢复——这正是用户拍板的需求。

## 二、数据设计

**新表** **`search_retrievals`（检索快照）**：

| 字段        | 类型             | 说明                                                               |
| --------- | -------------- | ---------------------------------------------------------------- |
| id        | varchar(32) PK | cuid                                                             |
| sessionId | varchar(32)    | 关联 search\_sessions（同租户外键语义）                                     |
| question  | varchar(512)   | 重写后的检索问题（生成时用原始问题，从 session 取）                                   |
| mode      | varchar(16)    | 检索模式                                                             |
| sources   | json           | 精排后的完整来源数组（含 idx/title/url/snippet/contentMd/sourceType/isCited） |
| createdAt | timestamp      | 创建时间（恢复窗口计时起点）                                                   |

- 迁移：新增 Prisma migration；**不登记租户隔离清单**（与 SearchReport 同理：经 sessionId 归属 session，行级隔离由 session 查询链保证）

- 恢复窗口：**30 分钟**（常量 `RETRIEVAL_TTL_MINUTES`，可后续挪 sys\_configs），过期后生成接口返回业务错误码（前端提示重新检索）

- 不删旧行：报告生成成功后快照保留（同一会话允许"重新选择再次生成"，PRD 3.2 要求）

## 三、API 设计

### 3.1 `POST /search/stream`（改造，语义变化 ⚠️）

管道在 rerank 完成后：落检索快照 → 推送全部 source 事件 → 发 `sources_ready { sessionId }` → **正常结束**（不再生成）。计费（consumeTrial）、限流、注入防护、敏感词等全部保持现有逻辑不动（检索段扣费，保护外部检索成本；生成段不重复扣）。

### 3.2 `POST /search/stream/generate`（新增，SSE）

- 入参：`{ sessionId: string, selectedIdxs: number[] }`（zod：非空、去重、1 起整数）

- 校验：快照存在且属于当前用户（经 session 租户链）；未超恢复窗口；selectedIdxs 均在快照来源范围内——任一不过返回 4xx 业务错误

- 流程：按 selectedIdxs 过滤快照 sources → **按勾选集合重新连续编号** → 生成（复用 GenerateService.stream + L4 输出兜底）→ 落库（复用 saveReport，未勾选来源落库但标未引用）→ done

- SSE 并发槽位：占用（与检索一致，防生成并发滥用）

### 3.3 `GET /search/retrievals/:sessionId`（新增，恢复选择态）

返回快照（sources + createdAt + 剩余有效秒数）。用于：历史记录中「待选择」会话点击恢复、前端刷新恢复。权限同上。

### 3.4 `GET /search/histories`（微调）f

列表项增加 `status: 'pending_selection' | 'done'`（有快照无报告 → 待选择），前端历史下拉对待选择会话点击 → 恢复选择态而非回首页重搜。

## 四、前端改造（frontend/web/src/views/SearchView\.vue 为主）

1. **选择态**：检索段 SSE 结束（收到 sources\_ready）后进入；来源卡复用现有勾选交互（checkedIdxs 已有）；「开始分析（基于勾选 N 条）」主按钮 + 「存入知识库」保留
2. **生成态**：调 generate 接口，复用现有流式渲染（report\_chunk/done 逻辑不变）
3. **重新选择**：生成完成/失败后「重新选择数据」按钮 → 清报告、回选择态（来源与勾选保留）
4. **恢复**：历史记录/刷新进入时，调 3.3 接口拉快照回选择态；过期则提示重新检索
5. api/search.ts：新增 generateStream（复用 searchStream 的 SSE 解析封装）、fetchRetrieval；SearchStreamHandlers 增加 sources\_ready 事件

## 七、风险与回归点

- SSE 协议变化对旧前端不兼容 → 同仓库前后端同步发，无独立客户端（风险低）

- 计费语义：检索扣费保持（用户搜完不生成也扣 1 次）——与现状一致，但交互上用户感知更明显（没出报告也扣了），需在配额引导文案上明确「检索即计费」

- bench-sse.mjs 压测脚本依赖 done 事件 → 需同步适配（一段式改两段式压测）

- 历史记录中旧会话（无快照）行为不变；新会话有快照无报告 → 待选择
