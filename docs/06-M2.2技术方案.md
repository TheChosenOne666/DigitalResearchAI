## 五、关键实现要点

### 意图分类（IntentService）
- Provider：`createOpenAI({ baseURL: ARK_BASE_URL, apiKey: ARK_API_KEY })`，model = `LLM_MODEL`（默认 `deepseek-v4-pro-ga-260813`）；备选 `LLM_FALLBACK_MODEL`。
- system 指令：从用户问题中抽取国家/指标/年份区间/检索倾向；`generateObject({ schema: SearchIntentSchema })`。
- 降级：无 `ARK_API_KEY` 或调用抛错 → 返回空 `SearchConditions`，跳过回填，原问题直走检索（不中断管道）。
- 合并：手动 `conditions` 非空字段覆盖 AI 结果（手动优先）。

### 联网路（WebAnySearchConnector）
- AnySearch：`POST https://api.anysearch.com/v1/search`，Body `{ query, max_results=10 }`；认证模式 Header `Authorization: Bearer <ANYSEARCH_API_KEY>`（免费 1000 次/天），无 Key 匿名模式（按客户端 IP 限流，额度较低，构造时打警告日志）。
  - 响应：`results[]` → `title/url/snippet/content`（content 为已清洗正文，直接作 `contentMd`）+ `metadata`（request_id 等，并入 meta）。
- 无需自建抓取/正文抽取（原「fetch + jsdom + Readability + turndown」链路已随切换移除）。
- 降级：请求失败/超时 → 返回空数组 + 警告日志，不抛出阻断管道。
- 联网查询词：默认用 `input.question`；若无则用 conditions 拼装。

### 阶段推送（controller）
```
stage:intent → classify → cond_fill → stage:searching → search(含 fusion) → source×(N) → stage:fusing → stage:done → done
```
`generating` 阶段留待 M2.3（流式生成）。
