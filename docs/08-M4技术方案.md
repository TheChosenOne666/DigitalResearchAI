## 三、数据模型设计

### 3.1 新增表 `workspace_reports`（分析结果报告）

分析结果报告与智搜报告（`search_reports`）字段差异大（图表配置/分析背景/指标口径），独立建表，不塞进 SearchReport 加可空字段。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | VarChar(32) cuid | 主键 |
| tenantId | VarChar(32) | 行级隔离 |
| userId | VarChar(32) | 创建人 |
| title | VarChar(255) | 报告标题（{指标} 数据分析报告） |
| contentMd | Text | 报告正文（Markdown，≥3000 字，14 章节） |
| paramsSnapshot | Json | 参数快照（国家/指标/年份/来源/图表配置） |
| sources | Json | 来源列表（编号/标题/链接/类型，供引文映射与存库） |
| tokenUsage | Int | token 用量 |
| status | VarChar(16) | 报告状态（DRAFT/ARCHIVED） |
| version | Int | 版本号（重新生成累加） |
| createdAt / updatedAt | DateTime | 时间戳 |

### 3.2 新增表 `workspace_datasets`（我的数据 = 收藏的数据集快照）

工作台「收藏到我的数据」落快照，离线可查、可溯源、可归档。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | VarChar(32) cuid | 主键 |
| tenantId / userId | VarChar(32) | 隔离 / 创建人 |
| name | VarChar(255) | 数据集名 |
| data | Json | 结构化时序快照（指标/国家/年份/值/来源） |
| tags | Json | 标签 |
| status | VarChar(16) | ACTIVE / ARCHIVED |
| sourceType | VarChar(16) | 来源（WDI / upload / 混合） |
| createdAt / updatedAt | DateTime | 时间戳 |

### 3.3 字段变更

- `SearchReport`：不改动。智搜报告与工作台分析报告在「我的报告」列表接口层聚合。
- 新表均登记 `tenant-filter.ts` 的 `TENANT_MODELS` 实现行级隔离。

## 四、接口设计

```
# 数据工作台
GET  /workspace/dataset      时序数据查询（countries/indicators/yearFrom/yearTo → 结构化 JSON）
POST /workspace/upload       Excel/CSV 上传补充（解析为时序数据并入）

# 分析结果
POST /workspace/analyze      生成分析结果（SSE 流式，固定章节 ≥3000 字）
GET  /workspace/reports/:id  分析结果报告详情

# 我的报告（聚合智搜 + 分析结果）
GET  /workspace/reports      我的报告列表（搜索/标签/状态/分页）
GET  /workspace/reports/:id/versions  版本列表

# 我的数据
GET    /workspace/datasets       我的数据列表（搜索/标签/状态/分页）
POST   /workspace/datasets       收藏到我的数据（快照）
POST   /workspace/datasets/:id/archive  归档/恢复
DELETE /workspace/datasets/:id   删除

# 导出（引文映射）
POST /report/export          Word/PPT 导出（入参：报告类型+id，回传二进制流）
```

接口细节：
- `GET /workspace/dataset`：复用 `fetchWdi`，按 countries/indicators/year 取数，返回 `{ indicator, series: [{country, values: {year: value}}] }` 结构化 JSON（区别于智搜的 Markdown 表格）。
- `POST /workspace/analyze`：SSE 复用 M2 的 `serializeSse`，但阶段更简（`stage` → `report_chunk` → `done{reportId}`），复用 `GenerateService.stream` + 固定章节 System prompt。
- 报告导出落审计（action=EXPORT）。

## 七、依赖变更（显式列出）

| 依赖 | 用途 | 说明 |
| --- | --- | --- |
| `docx`（后端） | Word 导出 | 章节排版 + 引文上标 + 文末来源表 |
| `pptxgenjs`（后端） | PPT 导出 | 封面/摘要/图表页/来源页 |
| `echarts`（前端） | 图表视图 | 折线/柱状/面积/雷达 + 导出 |

**刻意不引入**：`node-canvas` / `echarts` SSR（原生编译，Windows 环境风险高）。图表嵌入 Word/PPT 改用「前端 ECharts 渲染 → `getDataURL` 得 base64 → 随导出请求回传后端 → 后端嵌图」，规避编译问题。

## 九、风险

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 导出依赖（docx/pptxgenjs）与现有 pnpm 环境兼容 | 中 | 先装后 build 验证；版本对齐 Node 22 |
| 工作台依赖 WDI 外部 API 可用性 | 中 | 超时熔断返回空 + 前端空态提示（与 M2 一致） |
| 分析结果 LLM 无 Key 降级 | 中 | 复用 GenerateService 降级（输出结构化摘要），保证页面可渲染 |
| 分析结果正文 ≥3000 字不稳定 | 中 | System prompt 强约束章节与字数，降级路径给足内容量 |
