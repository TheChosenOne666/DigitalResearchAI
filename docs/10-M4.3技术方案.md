## 二、后端改动

### 2.1 Prisma 新增 `WorkspaceReport` 表（`prisma/schema.prisma`）

沿用 08 方案 3.1 字段，Prisma 实现：

```prisma
model WorkspaceReport {
  id             String   @id @default(cuid()) @db.VarChar(32)
  tenantId       String   @map("tenant_id") @db.VarChar(32)
  userId         String   @map("user_id") @db.VarChar(32)
  title          String   @db.VarChar(255)
  contentMd      String   @map("content_md")          // Text，14 章节正文
  paramsSnapshot Json?    @map("params_snapshot")     // 指标/国家/年份/来源/图表配置/统计/数据表
  sources        Json?                                 // 来源列表（编号/标题/链接/类型）
  tokenUsage     Int      @default(0) @map("token_usage")
  status         String   @default("DRAFT") @db.VarChar(16)
  version        Int      @default(1)
  createdAt      DateTime @default(now()) @map("created_at")
  updatedAt      DateTime @updatedAt @map("updated_at")

  @@index([tenantId, createdAt])
  @@map("workspace_reports")
}
```

- `tenant-filter.ts` 的 `TENANT_MODELS` 增加 `'WorkspaceReport'`。
- 生成后执行 `prisma generate` 更新 client。

### 2.2 新增 `workspace/analyze.ts`（纯函数，可单测）

```
computeStats(series, years) → { sampleCount, yearRange, yearCount, endAvg, changePct, completeness, nonNull, totalCells }
computeTable(series, years, topN) → { head, rows }     // Top N 排名降序，缺失 '..'
buildAnalyzePrompt(input, stats, table) → { system, prompt }
buildFallbackReport(input, stats, table) → string      // 确定性 14 章节 Markdown（无 Key/失败降级用）
```

- 统计口径与原型 `ssWSAnzBuild` 一致：期末均值简单算术平均、区间累计变动百分比、完整率 = 非空单元格 / 总单元格、排名按末年值降序（缺失末位）。
- `buildAnalyzePrompt`：把时序数据矩阵（Top N 表 + 全部样本统计）作为上下文，System prompt 强约束 14 个固定章节与总字数 ≥3000 字。
- `buildFallbackReport`：用确定性算法拼装与 LLM 同结构的 14 章节正文（数字来自 stats/table，文字用模板），保证无 Key 时页面仍完整可渲染。

### 2.3 `GenerateService` 扩展（最小改动，M2 行为不变）

新增底层方法（公开、带文档注释）：

```ts
streamCustom(
  input: { system: string; prompt: string; fallbackText: string },
  signal: AbortSignal,
  onChunk: (chunk: GenerateChunk) => void,
): Promise<GenerateResult>
```

- `stream()` 内部改为调用 `streamCustom`（`system=GENERATE_SYSTEM`、`prompt=buildGeneratePrompt(...)`、默认降级文本），M2 调用方与既有单测不受影响。
- `streamCustom` 无 Key/失败时降级输出 `fallbackText`（不阻断管道，与现状一致）。

### 2.4 新增 `workspace/workspace.store.service.ts`

```
saveReport(input) → { id }            // create workspaceReport（tenantId 由租户 Extension 注入）
reportDetail(id) → ReportDetail       // 跨租户/不存在 → 404
```

`ReportDetail`：id / title / contentMd / paramsSnapshot / sources / tokenUsage / createdAt / status / version。

### 2.5 `workspace.service.ts` 新增 `analyze()` 与 `saveToKb()`

- `analyze(input, signal, onChunk)`：`computeStats` + `computeTable` → `buildAnalyzePrompt` + `buildFallbackReport` → `generate.streamCustom` → `store.saveReport` 落库 → 返回 `{ reportId }`。落库内容含 `paramsSnapshot`（指标/国家/年份/来源/图表配置/统计/数据表，供前端渲染统计卡片与数据表）与 `sources`。
- `saveToKb(reportId, body)`：读 `reportDetail` 校验归属 → 校验库/分组（复用 `KbStoreService`）→ 把 `# 标题 + contentMd` 作为一份 `md` 文档经 `KbStoreService.createDocument` 落库（`status=PENDING`，`sourceSessionId=reportId`）→ 返回 `{ created, documents }`。

### 2.6 `workspace.controller.ts` 新增三个接口

```
POST /workspace/analyze          SSE 流式（body: indicator/countries/years/series/sources/chartConfig）
                                事件：stage → report_chunk → done{reportId}（复用 serializeSse）
GET  /workspace/reports/:id      报告详情（JSON）
POST /workspace/reports/:id/save-kb  整份报告存入知识库（body: libraryId/groupId?/visibility?/tags?）
```

- `analyze` 用 POST + body（时序矩阵数据量大，不走 query），响应 `text/event-stream`，客户端断开 `AbortController` 全链路取消（对齐 `search/stream`）。

### 2.7 模块接线

- `SearchModule` 的 `exports` 增加 `GenerateService`。
- `WorkspaceModule` 的 `imports` 增加 `PrismaModule`、`KbModule`、`SearchModule`。

## 三、前端改动（frontend/web）

### 3.1 `api/workspace.ts`

- 新增 `AnalyzeReport` / `AnalyzeParams` 类型与 `analyzeStream(params, handlers, signal)`：POST `/api/v1/workspace/analyze` 读流，解析 `stage/report_chunk/done/error`（参照 `search.ts` 的 `searchStream` 解析逻辑）。
- 新增 `fetchAnalyzeReport(id)`（GET 详情）、`saveAnalyzeToKb(id, body)`（POST 存库）。

### 3.2 新增 `views/AnalyzeResultView.vue`（独立页，路由 `/workspace/analyze/:id`）

页面结构对齐原型 `view-ws-analyze`（9.27）：
- 页头：标题「分析结果」+ 副文案 + 操作按钮（返回工作台 / 下载文件 / 存入知识库）；
- 头部信息条（报告标题 / 生成时间 / 指标 / 数据源 / 覆盖国家数）；
- 统计卡片 5 枚（样本覆盖 / 时间跨度 / 期末均值 / 区间变动 / 数据完整率，取 `paramsSnapshot.stats`）；
- 报告正文 14 章节（`contentMd` 经 `MarkdownView` 渲染）；
- 数据分析表（取 `paramsSnapshot.table`）；
- 数据来源列表（取 `sources`）；
- 底部说明（缺失值 `..` 占位 · AI 生成仅供研究参考）。

生成态：工作台点击「生成分析结果」后，先在工作台内弹进度，SSE 收到 `done{reportId}` 后 `router.push('/workspace/analyze/'+reportId)`。

### 3.3 `WorkspaceView.vue`

「生成分析结果」按钮由占位改为真实触发：组装 `AnalyzeParams`（当前指标 `indicator` + 合并后 `series` + `years` + `sourceLabel` + 图表配置）→ 调 `analyzeStream` 流式展示进度 → 跳转分析结果页。

### 3.4 `router/index.ts`

新增 `/workspace/analyze/:id` 路由（`meta.requiresAuth: true`，组件 `AnalyzeResultView`）。`TopNav` 的 `activeNav` 已按 `startsWith('/workspace')` 命中，无需改。

## 六、决策点（本次默认，如无异议按此实施）

| # | 决策 | 默认结论 | 理由 |
| --- | --- | --- | --- |
| Q1 | 分析数据输入 | **前端传合并时序数据**（含本地文件） | 本地文件仅前端会话态，后端重取 WDI 会丢失；且与 D1「不落库」一致 |
| Q2 | 统计卡片/数据表由谁算 | **后端确定性计算**，LLM 只写文字章节 | 数字准确、降级可渲染、避免 LLM 幻觉 |
| Q3 | 下载范围 | **M4.3 仅导出 Markdown** | Word/PPT + 引文映射属 M4.4（08 方案 D3），避免提前引入 docx/pptxgenjs |
| Q4 | 存库粒度 | **整份报告存一份 md** | 对齐原型 `ssWSAnzSaveKb`（整份存，非逐来源） |
