## 二、架构决策（2026-08-28 拍板）

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| **D1** | 管理端走**平台级跨租户**数据访问：AdminModule 注入 `PrismaService` 本体（系统 client），不使用 `forTenant` | `PrismaService` 继承 `PrismaClient`，只有 `forTenant` 才挂租户 Extension（见 `common/prisma/prisma.service.ts`）。管理端用本体即可跨租户查询；租户上下文拦截器仍会写入 ctx，但不影响系统 client |
| **D2** | M6 新增表**一律不登记** `TENANT_MODELS` | 管理端表为平台级公共数据（参数/字典/指标/分类等）；含 `tenantId` 字段的表（datasets/import_tasks/messages）仅作归属标记，不做行级强制注入，避免管理端查询被误过滤 |
| **D3** | 接口统一前缀 `/api/v1/admin`，按功能分子控制器 | 与业务模块（`kb` / `member` / `search`）隔离，避免污染用户端语义；M3 已在 `kb/reviews` 埋的审核雏形保留不动，M6.5 在 admin 下提供跨租户版本 |
| **D4** | 权限矩阵用**角色常量 + `@Roles`** 表达，一期不建权限表 | 原型 A-04 明确"一期不开放自定义角色"；三内置角色权限固定，前端菜单按角色过滤、后端接口按 `@Roles` 拦截，双保险 |
| **D5** | 基础设施型功能（备份恢复/向量索引重建/运行监控）做**记录 + 任务占位，不真执行** | 备份仅落 `backup_records` 与 `sys_tasks`（不调 `pg_dump`）；索引重建/增量/清理仅落任务记录不改 Qdrant；运行监控**真实**探测（复用 `HealthModule` 的 PG/Redis/Qdrant 检查 + API 自身）。页面在按钮旁标注"演示环境未执行真实操作" |
| **D6** | 管理员账号由**独立 seed 脚本**创建（`admin/admin123`），不做启动种子 | 启动种子会在生产持续创建弱口令账号，不安全。脚本幂等：已存在则只补角色/密码 |
| **D7** | 前端**不引入 ECharts**，趋势图用纯 CSS 柱状（对齐原型 `mini-bar`） | 管理端图表需求简单（KPI 趋势/迷你柱），原型本身也是 CSS 实现，避免为管理端新增依赖 |
| **D8** | 敏感词命中在**智搜入口前置拦截**（M6.3 实现），审计落 `audit_logs` | 原型 A-10 明确"命中策略：拦截该次检索并提示，记录日志供审计" |

### 4.3 接口清单（全量，按批次）

#### M6.1

| 方法 | 路径 | 说明 | 角色 |
| --- | --- | --- | --- |
| GET | `/admin/me` | 当前管理员：用户/角色/可见菜单 | 管理员 |
| GET | `/admin/dashboard/overview` | 运营看板：`?range=today\|7d\|30d` | 管理员 |

`overview` 响应：
```ts
{
  kpis: { totalUsers, newUsers, totalSearches, todaySearches, incomeCents },
  trends: { userTrend: {date,newUsers,activeUsers}[], searchTrend: {date,count}[] },
  todos: { importPending, kbReviewPending, expiringMembers },
  overview: { activeUsers, avgSearches, reportCount, newChunks }
}
```
口径：
- `totalUsers` = `users.count()`；`newUsers` = 窗口内 `createdAt`；`activeUsers` = 窗口内有 `lastLoginAt`
- `totalSearches` = `search_sessions.count()`；`todaySearches` = 今日
- `incomeCents` = 窗口内 `member_orders.status=PAID` 的 `amountCents` 求和
- `reportCount` = 窗口内 `workspace_reports.count()`；`newChunks` = 窗口内 `kb_chunks.count()`
- `expiringMembers` = `member_subscriptions.expireAt` 在 7 天内且 `level != FREE`
- `kbReviewPending` = `kb_documents.status=PENDING`；`importPending` = `import_tasks.status=PENDING`
- 统计失败降级：单项失败返回 0 并置 `degraded: true`（对齐 Health 的降级表达）

### 6.12 实施备注

- **D8 拦截测试踩坑**：curl 直接传中文 question 未 URL 编码，Node HTTP 服务器返回 400 Bad Request + 空 body，误判为拦截异常；正确方式 `curl -G --data-urlencode "question=中文"`，此时返回 403 + `{"code":2001,"message":"内容包含敏感词..."}`；验证 hitCount=1 + audit_logs SEARCH_BLOCKED=1
- **D8 拦截位置**：必须在 `res.setHeader('Content-Type','text/event-stream')` 之前，否则 SSE 响应头已 flush，异常处理后 body 无法写入
- **schema import_tasks 无 FK submitter 关系**（M6.1 一次性建表时未加 `submitter User @relation`）：list 改为手动批量查 users 组装 submitter 显示名；避免后续 schema 迁移
- **数据集 approve 写 fieldCount**：从 `import_tasks.preview.headers.length` 提取（约定 `{ headers: string[], rows: unknown[][] }`），无法识别时回退 0
- **已发布公告禁编辑**：避免用户端正在阅读的公告被后台改文案造成不一致，提示先撤回再编辑
- **后台任务通知**：根据系统提示，后台 dev:api 任务会通过 `<task-notification>` 自动通知完成，无需轮询
