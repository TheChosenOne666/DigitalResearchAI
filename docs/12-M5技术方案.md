# AI数智研究平台 · M5 技术方案（会员计费支付）

> 版本：v1.0 ｜ 日期：2026-08-28
> 前置：`04-开发规划.md`（M5 范围/验收已定义）、M0~M4 已交付
> 界面依据：`AI数智研究平台原型/index.html`（9.x 会员中心 v3.4 / 个人中心·结算支付 / 个人中心·账单查询）
> 原则：支付渠道走适配器（MOCK 先行），订单状态机与回调幂等按生产标准实现；套餐落库供 M6 管理端复用

## 一、范围与验收

| 板块 | 内容 | 原型依据 |
| --- | --- | --- |
| 套餐与会员 | 专业版 / 企业版 × 单月 / 连续包月 / 年付；会员状态卡（等级·周期·到期日·剩余天数） | 会员中心 v3.4（`VIP.PLANS` / `VIP.CYCLES`） |
| 下单与支付 | 下单 → 确认支付 → MOCK 收银台 → 异步回调 → 入账生效；订单状态机；扫码/轮询查单 | 结算支付（U-16） |
| 支付渠道 | `PayChannel` 适配器接口 + MOCK 实现（HMAC 签名验签）；WECHAT / ALIPAY 预留 | — |
| 回调幂等 | 流水号唯一 + 状态机守卫；重放不重复入账、不重复延期 | — |
| 续费 | 到期日累加（续费在原到期日上叠加）；连续包月到期懒续费生成下一期订单 | U-16 / A-03 |
| 账单 | 订单列表 + 支付流水双页签（时间/状态筛选） | 账单查询（U-17） |
| 配额拦截 | 非会员免费体验 1 次智搜（Redis 原子计数）+ 开通引导 | 会员中心 v3.4 `vipCanSearch` |

**已确认决策（2026-08-28）**：

| # | 决策 | 结论 |
| --- | --- | --- |
| D1 | 支付渠道 | **适配器 + MOCK 渠道**：签名验签/回调幂等/状态机按生产实现，MOCK 走 HMAC；后续加 WECHAT/ALIPAY 只换适配器，业务代码零改动 |
| D2 | 连续包月 | **标记 + 到期懒续费**：订阅记 `autoRenew`，到期后用户访问会员中心/订阅接口时自动生成下一期 PENDING 订单；不引入定时任务与代扣签约 |
| D3 | 套餐数据 | **落库 `member_plans` + seed**（对齐原型 `VIP.PLANS` 价格），M6 管理端可复用同一份数据增删改 |
| D4 | 配额范围 | **仅拦截 AI 智搜**（对齐原型 `vipCanSearch`）；工作台/知识库/报告不拦 |
| D5 | 发票 | **本期不做**（原型无对应界面），仅订单 + 支付流水 |

**验收**（对齐开发规划 M5）：
- 完整闭环：购买 → 使用（智搜不限次）→ 续费（到期日累加）→ 账单可查；
- 回调重放不重复入账、不重复延期；
- 非会员第 2 次智搜被拦截并弹出开通引导。

## 二、数据设计

### 2.1 新增枚举与表（Prisma）

```prisma
// ===== M5 会员计费域 =====

/// 会员等级
enum MemberLevel { FREE PRO ENTERPRISE }

/// 购买周期
enum PlanCycle { SINGLE MONTHLY YEAR }

/// 订单状态机：PENDING → PAID（终态）/ CANCELLED / CLOSED / FAILED
enum OrderStatus { PENDING PAID CANCELLED CLOSED FAILED }

/// 支付渠道
enum PayChannel { MOCK WECHAT ALIPAY }

/// 会员套餐（平台级，全租户共享；不纳入 TENANT_MODELS）
model MemberPlan {
  id               String     @id @default(cuid()) @db.VarChar(32)
  /// 套餐编码（唯一，如 PRO_MONTHLY）
  code             String     @unique @db.VarChar(32)
  level            MemberLevel
  cycle            PlanCycle
  /// 展示名（专业版·连续包月）
  name             String     @db.VarChar(64)
  /// 卖点标签（个人研究首选 / 企业级容量）
  tag              String?    @db.VarChar(64)
  /// 售价（分）
  priceCents       Int        @map("price_cents")
  /// 划线原价（分，仅年付有）
  originPriceCents Int?       @map("origin_price_cents")
  /// 权益列表，JSON 字符串数组
  features         Json?
  /// 排序（同 level 内按周期升序）
  sort             Int        @default(0)
  enabled          Boolean    @default(true)
  createdAt        DateTime   @default(now()) @map("created_at")
  updatedAt        DateTime   @updatedAt @map("updated_at")
  @@map("member_plans")
}

/// 用户会员订阅（每用户一条，记录当前会员态）
model MemberSubscription {
  id         String      @id @default(cuid()) @db.VarChar(32)
  tenantId   String      @map("tenant_id") @db.VarChar(32)
  userId     String      @unique @map("user_id") @db.VarChar(32)
  /// 当前等级（无会员为 FREE）
  level      MemberLevel @default(FREE)
  /// 当前周期（FREE 时可空）
  cycle      PlanCycle?
  /// 到期时间（含当日最后时刻）
  expireAt   DateTime?   @map("expire_at")
  /// 连续包月自动续费开关
  autoRenew  Boolean     @default(false) @map("auto_renew")
  /// 累计开通次数
  totalPeriods Int       @default(0) @map("total_periods")
  createdAt  DateTime    @default(now()) @map("created_at")
  updatedAt  DateTime    @updatedAt @map("updated_at")
  @@index([tenantId, expireAt])
  @@map("member_subscriptions")
}

/// 会员订单（一期一单；连续包月每期一单）
model MemberOrder {
  id          String      @id @default(cuid()) @db.VarChar(32)
  tenantId    String      @map("tenant_id") @db.VarChar(32)
  userId      String      @map("user_id") @db.VarChar(32)
  /// 业务订单号（ORD + yyyymmddHHMMSS + 6 位随机），对外暴露
  orderNo     String      @unique @map("order_no") @db.VarChar(32)
  planId      String      @map("plan_id") @db.VarChar(32)
  /// 下单时套餐快照（名称/等级/周期/金额），JSON
  planSnapshot Json       @map("plan_snapshot")
  /// 金额（分）
  amountCents Int         @map("amount_cents")
  channel     PayChannel  @default(MOCK)
  status      OrderStatus @default(PENDING)
  /// 支付成功后生效的会员区间
  periodStart DateTime?   @map("period_start")
  periodEnd   DateTime?   @map("period_end")
  /// 渠道预支付参数（MOCK：收银台地址），JSON
  payInfo     Json?       @map("pay_info")
  paidAt      DateTime?   @map("paid_at")
  /// 过期时间（PENDING 超时关单）
  expireAt    DateTime?   @map("expire_at")
  /// 连续包月自动生成的续费单标记
  isRenewal   Boolean     @default(false) @map("is_renewal")
  createdAt   DateTime    @default(now()) @map("created_at")
  updatedAt   DateTime    @updatedAt @map("updated_at")
  @@index([tenantId, createdAt])
  @@index([userId, status])
  @@map("member_orders")
}

/// 支付流水（一笔订单一次成功回调；transactionNo 唯一保证幂等）
model PaymentRecord {
  id            String   @id @default(cuid()) @db.VarChar(32)
  tenantId      String   @map("tenant_id") @db.VarChar(32)
  orderId       String   @map("order_id") @db.VarChar(32)
  orderNo       String   @map("order_no") @db.VarChar(32)
  /// 渠道流水号（唯一，幂等键）
  transactionNo String   @unique @map("transaction_no") @db.VarChar(64)
  channel       PayChannel
  /// 金额（分）
  amountCents   Int      @map("amount_cents")
  /// 回调原始报文，JSON
  rawPayload    Json?    @map("raw_payload")
  status        String   @default("SUCCESS") @db.VarChar(16)  // SUCCESS / FAILED
  paidAt        DateTime @default(now()) @map("paid_at")
  createdAt     DateTime @default(now()) @map("created_at")
  @@index([tenantId, createdAt])
  @@index([orderId])
  @@map("payment_records")
}

/// 免费体验配额（终身 1 次；Redis 为主，本表持久化兜底 + 对账）
model TrialQuota {
  id        String   @id @default(cuid()) @db.VarChar(32)
  tenantId  String   @map("tenant_id") @db.VarChar(32)
  userId    String   @unique @map("user_id") @db.VarChar(32)
  usedCount Int      @default(0) @map("used_count")
  updatedAt DateTime @updatedAt @map("updated_at")
  @@map("trial_quota")
}
```

- `TENANT_MODELS` 增加：`MemberSubscription` / `MemberOrder` / `PaymentRecord` / `TrialQuota`。
- **`MemberPlan` 不登记**（平台级公共数据，全租户共享）。
- 全为新增表，无破坏性变更。

### 2.2 金额口径

- 库内一律存 **分（Int）**，避免浮点；接口返回同时给 `amountCents` 与 `amount`（元，字符串/数值）。
- 原型价格（元）：专业版 单月 59 / 连续包月 49 / 年付 499（划线 708）；企业版 单月 399 / 连续包月 329 / 年付 3999（划线 4788）。

### 2.3 到期日累加规则

```
base = (当前订阅有效 && 同 level) ? max(now, expireAt) : now
periodStart = base
periodEnd   = base + 1 个月（SINGLE / MONTHLY）| + 1 年（YEAR）
```

- 跨周期升级（专业版 → 企业版）：不累加，从 `now` 起算（等级不同，权益不同，原型亦为「切换/升级」）。
- 同周期续费：在原到期日上累加（未到期续费不浪费天数）。

## 三、接口设计

统一前缀 `/api/v1`，受全局 `SessionAuthGuard` 保护；回调接口 `@Public`。

### 3.1 套餐与会员（MemberController `/member`）

```
GET  /member/plans            套餐列表 → { levels: [{ level, name, tag, plans: [...] }] }
GET  /member/subscription     当前会员状态 + 免费体验剩余（含懒续费触发）
POST /member/orders           下单 { planId, channel } → { orderNo, amount, status, payInfo }
POST /member/orders/:orderNo/pay     发起支付 → { payInfo: { cashierUrl, orderNo, amount, expireAt } }
POST /member/orders/:orderNo/cancel  取消订单（仅 PENDING）
GET  /member/orders           我的订单（status/keyword/page/pageSize）
GET  /member/orders/:orderNo  订单详情（前端轮询支付结果用）
GET  /member/orders/pending   待支付订单（支付中心顶部卡片）
POST /member/subscription/auto-renew  连续包月开关 { enabled }
```

`GET /member/subscription` 返回：

```ts
{
  isMember: boolean,
  level: 'FREE' | 'PRO' | 'ENTERPRISE',
  cycle: 'SINGLE' | 'MONTHLY' | 'YEAR' | null,
  expireAt: string | null,
  daysLeft: number,
  autoRenew: boolean,
  trialLeft: number,          // 非会员免费体验剩余次数（会员为 Infinity → 前端改判）
  pendingOrder: {...} | null  // 待支付订单（支付中心联动）
}
```

### 3.2 支付渠道与回调（PayController `/pay`）

```
POST /pay/notify/:channel    @Public 渠道回调：验签 → 幂等 → 入账 → 会员生效（渠道名大小写不敏感）
```

**MOCK 收银台取舍（实施结论）**：不建独立收银台页面——真实渠道的 `payInfo.cashierUrl` 由渠道适配器生成并落库，
MOCK 场景下前端在「确认支付」弹窗内直接调 `POST /member/orders/:orderNo/mock-pay`
（服务端自签名后走**同一条** `handleNotify` 入账链路）。少一个页面、少一个 Public 查询接口，
且模拟支付与真实回调共用幂等逻辑，重放测试覆盖的就是生产路径。

回调入参（MOCK）：

```json
{ "orderNo": "ORD...", "transactionNo": "MOCK...", "amountCents": 49900,
  "timestamp": 1780000000000, "sign": "<HMAC-SHA256>" }
```

签名：`sign = HMAC_SHA256(PAY_MOCK_SECRET, "orderNo|amountCents|transactionNo|timestamp")`，常量时间比较。

**幂等与状态机（核心）**：

| 场景 | 处理 |
| --- | --- |
| `transactionNo` 已存在 | 直接返回 `SUCCESS`，不重复入账 |
| 订单已 `PAID` | 返回 `SUCCESS`，不重复延期 |
| 订单非 `PENDING`（已取消/关闭） | 记 `FAILED` 流水 + 返回失败，不改订单 |
| 金额与订单不符 | 记 `FAILED` 流水 + 返回失败 |
| 验签失败 | 400，不落流水 |
| 正常 | 事务内：订单 → PAID + 写 periodStart/periodEnd + 写流水 + upsert 订阅（累加到期日 + totalPeriods++） |

### 3.3 账单（BillingController `/billing`）

```
GET /billing/orders     订单列表（range: all|30d|90d，status 筛选，分页）
GET /billing/payments   支付流水列表（分页）
```

### 3.4 配额拦截（Redis）

- 键 `trial:used:{userId}`（无 TTL，终身 1 次）。
- 智搜入口（`SearchService` 生成前）调用 `QuotaService.consumeTrial(userId)`：
  - 会员 / 平台管理员 → 直接放行；
  - `INCR` 原子自增 → 结果 `> 1` → `DECR` 回滚 + 抛 `402 PAYMENT_REQUIRED`（错误码 `TRIAL_QUOTA_EXHAUSTED`），前端弹开通引导；
  - 通过 → 同步 `upsert` 到 `trial_quota` 表（持久化对账）；Redis 不可用时降级读表。
- 前端：HomeView 捕获该业务码 → 打开会员开通弹窗（对齐原型引导）。

## 九、风险

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 回调并发导致重复入账 | 高 | `transactionNo` 唯一约束 + 事务内状态机守卫（`updateMany where status=PENDING` 影响行数判定） |
| 到期日累加跨月进位错误 | 中 | `calcPeriodEnd` 纯函数单测覆盖 1/31、2/29 等边界 |
| Redis 配额计数丢失 | 中 | `trial_quota` 表持久化对账；Redis 不可用时降级读表（保守放行/拦截可配） |
| 懒续费重复生成订单 | 中 | 按 `(userId, periodStart)` 幂等查重，已存在 PENDING/PAID 续费单则跳过 |
| MOCK 与真实渠道差异被低估 | 中 | 适配器接口按微信/支付宝共性抽象（下单返 payInfo、异步回调、查单），接口形状稳定后再接真实渠道 |
| 管理端 A-03 复用套餐 | 低 | 套餐已落库且字段含 enabled/sort，M6 直接 CRUD |

### 附：M5.5 联调补充（dev-login）

**问题**：UI 联调完整购买闭环需多用户（会员用户 A + 非会员用户 B）切换验证；短信 60s 冷却（`sms:cd:{phone}`）导致第二轮登录被 429 拦截，无法在浏览器快速切换账号。

**方案**：新增开发期 API 登录 `POST /auth/dev-login`，复用 `smsLogin` 的 `findUserWithRoles` / `createUserWithTenant` / `buildLoginResult` 逻辑，仅跳过 `verifyCode`。由 `DEV_LOGIN_ENABLED` 环境变量守卫：未配置或非 `true` 时接口返回 **404 隐藏存在**（生产探测不到），开启后联调脚本可直接拿 `sessionId` 注入 `localStorage['web.sessionId']`，Puppeteer 一行 `page.evaluate` 完成"换号"。

**取舍**：相比"清 Redis 冷却键"或"等 60s 冷却"，dev-login 一次配置长期生效、零等待、跨进程可用；唯一代价是 auth 模块多一个仅 11 行的 controller 方法 + 一个 service 方法，关闭后无任何运行时影响。
