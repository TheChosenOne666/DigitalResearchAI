## 三、API 设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/search/stream` | 智搜 SSE。query 参数：`question`、`mode`(hybrid/web/local)、`conditions`(可选 JSON，手动指定优先于 AI)、`sessionId`(query 兜底鉴权，EventSource 无法带 header) |
| GET | `/api/v1/search/histories` | 历史会话列表（分页，租户隔离） |
| GET | `/api/v1/search/reports/:id` | 报告详情（含来源列表） |
| POST | `/api/v1/search/reports/:id/save-kb` | 勾选来源存知识库（M2 留接口桩，M3 接入库流程） |

> `/search/stream` 是核心：一次请求 → SSE 长连接 → 五阶段事件流式推送。

## 四、数据库表（Prisma schema 新增）

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `search_sessions` | id, tenantId, userId, question, mode, conditions(Json), createdAt | 一次智搜会话 |
| `search_reports` | id, sessionId, contentMd, paramsSnapshot(Json), tokenUsage, createdAt | 报告版本（可多版本，最新版参与展示） |
| `search_sources` | id, reportId, idx, title, url, snippet, sourceType(web/vertical/local), isCited, meta(Json) | 来源卡 + 引用级/参考级标记 |

迁移：`prisma migrate dev --name search_pipeline`。

## 五、SSE 五阶段协议

事件用 `event:` / `data:` 格式（SSE 标准），`data` 为 JSON：

| event | data | 时机 |
| --- | --- | --- |
| `stage` | `{stage, msg}` stage ∈ intent/searching/fusing/generating/done | 阶段切换先行推送（首字节 ≤3s） |
| `cond_fill` | `{conditions:{countries[],indicators[],yearFrom,yearTo,routeHints}}` | 意图分类完成 → 回填条件栏（前端转 has-val 深色态，可手动微调） |
| `source` | `{idx,title,url,snippet,sourceType,isCited}` | 融合后逐个推送来源卡（引用级 isCited=true 进上下文） |
| `report_chunk` | `{text,citations[]}` | 流式正文片段，`citations` 为本片段出现的 `{c:N}` 编号 |
| `done` | `{sessionId,reportId}` | 生成结束 |
| `error` | `{message,stage}` | 任一阶段失败（不中断已推内容，最后发 error） |

中止：客户端断开连接 → NestJS 捕获 `close` 事件 → AbortController.abort() → LLM 流 + 抓取 Promise 取消。

## 六、意图分类（M2.2）

- 方舟 DeepSeek-V4-Pro-GA，OpenAI 兼容调用，`response_format`/工具函数驱动结构化输出
- Zod schema 单一事实源（packages/shared）：`{intent, countries[], indicators[], yearFrom, yearTo, routeHints}`
- 用户手动 `conditions` 优先于 AI 结果（后端 merge）
- 失败降级：意图分类失败 → 仅用原问题走联网路（不回填条件，仍能出结果）

## 七、三路检索（M2.1/M2.2）

**SearchConnector 统一接口**：
```ts
interface SearchConnector {
  search(input: ConnectorInput, signal: AbortSignal): Promise<SearchHit[]>;
}
interface SearchHit { title; url?; snippet; contentMd?; sourceType; meta?; rawScore? }
```

- **垂直路**（M2.1）：世界银行 WDI API（`https://api.worldbank.org/v2/country/{code}/indicator/{code}?date=...&format=json`），按意图的 countries/indicators/year 查，映射成时序数据集，contentMd 为表格 Markdown。指标字典映射（标准指标→WDI code）。
- **联网路**（M2.2）：AnySearch 聚合搜索直连（`POST https://api.anysearch.com/v1/search`，Body `{ query, max_results }`），响应 `results[]` 含 title/url/snippet/content（正文已清洗，直接作 contentMd），无需自建抓取与正文抽取。认证模式 Bearer `ANYSEARCH_API_KEY`（免费 1000 次/天），无 Key 匿名模式按 IP 限流。
- **本地路**：M2 返回空桩（`[]`），M3 知识库接入复用 fusion 代码。
- 三路 `Promise.allSettled` 并行，单路超时熔断（联网 15s / 垂直 10s / 本地 3s），一路失败不阻塞整体。

## 八、融合（rerank 降级，M2.1）

- **RRF**：`score(d) = Σ 1/(60 + rank_i(d))`；本地路命中加权 ×1.2（纯函数，单测）
- **SimHash 去重**：64 位 SimHash，汉明距离 ≤3 视为重复，保留得分高者（纯函数，单测）
- **截断 TopK**（默认 10，库级可配）：RRF 分数降序截断，分引用级（TopK 进 Agent 上下文 + 来源卡）/ 参考级（仅来源卡）
- rerank 降级：无精排，质量打折但管道可用；后续接独立 rerank 再加精排层

## 九、流式生成（M2.3）

- Vercel AI SDK 5.x `streamText`，provider = `@ai-sdk/openai`（OpenAI 兼容）配 `baseURL=方舟` + `apiKey=ARK_API_KEY` + `model=deepseek-v4-pro-ga-260813`
- Prompt 结构：系统指令（分析报告文体）+ 结构化数据表（垂直路）+ 引用级上下文（带编号 `{c:1..N}`）+ 用户问题
- 输出约定 `{c:N}` 引文标记 → 前端渲染角标 ↔ 来源卡黄色高亮联动
- 流式分片推送 `report_chunk`（按 token/句子切，含本片段 citations）

## 十、落库 + 用量（M2.3 ✅）

- 会话先建（stage=intent 时落 `search_sessions`，conditions 回填后一并快照保存）
- 生成结束落 `search_reports`（contentMd + paramsSnapshot + tokenUsage）+ `search_sources`（带 idx/isCited）
- 租户隔离：会话/报告/来源全走 `PrismaService.forTenant`（Extension 自动注入 tenant_id）；报告/来源无独立租户列，通过所属 session 嵌套写保证行级隔离；`SearchStoreService.requireTenant()` 缺上下文抛 1001
- 用量：`search_usage` 按 `(tenantId,userId,day)` 复合唯一 upsert（`searchCount+1` / `tokenUsage` 累加），走系统 client 显式 tenant_id 避开 Extension 对 upsert where 注入；无租户上下文时跳过不阻断主流程

## 十二、风险与降级

| 风险 | 降级 |
| --- | --- |
| 方舟延迟/不稳 | 备选豆包 Seed（同平台切 model）+ 阶段超时熔断 |
| AnySearch 无 Key | 匿名模式仍可调用（按 IP 限流，额度较低）；请求失败返回空 + 警告，管道不阻断 |
| 意图分类失败 | 跳过条件回填，原问题直接走联网路 |
| AnySearch 服务不可用/额度耗尽 | 联网路熔断返回空；SearchConnector 插槽可快速切换备选供应商 |
| SSE 长连接占用 | 网关超时 + 心跳；单实例连接上限告警（M7 调优） |
