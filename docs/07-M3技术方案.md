## 四、数据设计（Prisma schema 新增）

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `kb_libraries` | id, tenantId, name, visibility(PRIVATE/PUBLIC), color, description, topK, threshold, weight, chunkMode(FIXED/SMART), chunkSize, chunkOverlap, embedModel, learnStatus?, createdAt | 知识库 + 检索/向量化配置 |
| `kb_groups` | id, tenantId, libraryId, name, createdAt | 库内分组 |
| `kb_documents` | id, tenantId, groupId, name, mimeType, size, status(PENDING/LEARNING/READY/FAILED/INTERRUPTED), failReason, chunkCount, createdAt, updatedAt | 文档 + 学习状态机 |
| `kb_chunks` | id, tenantId, documentId, groupId, libraryId, index, content, keywords?, vectorId, createdAt | 切片（content 用于 PG 全文，vectorId 关联 Qdrant） |

- `kb_*` 四表统一带 `tenantId` 列，全部登记进 `TENANT_MODELS` 实现行级隔离。
- 迁移：`prisma migrate dev --name kb_rag`。
- Qdrant：每租户每库一个 collection（`tenant_{tenantId}_lib_{libraryId}`），payload 存 `{chunkId, documentId, groupId, tenantId}`，便于删除清理。

## 五、文档状态机（对齐原型 9.12）

```
上传/存入 → LEARNING（学习中断可 继续学习）→ READY（参与智搜检索）
                      └→ FAILED（可重新学习）
```

- 上传 → 状态 `LEARNING`，入 BullMQ 队列；队列消费：解析 → 切片 → 向量化 → 写 Qdrant + PG。
- 中断（进程重启/取消）：状态 `INTERRUPTED`，`relearn` 可继续。
- 失败（解析/嵌入异常）：状态 `FAILED` + failReason，`relearn` 可重跑。

## 六、切片与向量化

**切片（M3.2，纯函数可单测）**
- 固定长度：按 chunkSize 切字符，`chunkOverlap` 重叠衔接。
- 智能分段：按标题/段落/空行/句子边界优先断句，超长再按固定长度截断（前端配置中选择 固定长度/智能）。

**向量化（M3.2）**
- 方舟 embedding 模型（OpenAI 兼容 `/embeddings`），模型名走 `kb.libraries.embedModel`。
- **降级**：无 `ARK_API_KEY` 时 skp 向量化（vectorId 为空），检索退化为 PG 全文（不阻断，等 Key 后 `relearn` 补齐）。

---

## 七、混合检索（M3.3）

- 复用管道 `local.connector.ts`，注入 `KbRetrieverService.search()`。
- 向量路：Qdrant 按租户库 collection 检索 TopN，payload 过滤租户/库/分组。
- 全文路：PG `kb_chunks` 按 `to_tsquery`/`ilike` 检索 TopN。
- RRF 融合（复用 `fusion/rrf.ts`）+ 阈值截断 → 映射 SearchHit（title=文档名，snippet=切片片段，contentMd=切片 content，sourceType='local'，meta={libraryId,groupId,documentId,idx}，rawScore=相似度）。
- 三模式路由：`mode=local` 仅本地路；`mode=web` 仅联网+垂直；`mode=hybrid` 全开（本地优先，fusion 已内建 localWeight ×1.2）。

## 八、召回测试（M3.4）

- 输入测试问题 → 走本地检索层 → 返回命中文档片段 + 相似度分级（高 ≥0.7 / 中 ≥0.4 / 低 <0.4）。
- 前端点击片段查看原文（documentId + 切片上下文）。

## 九、入库链路（M3.4）

- 智搜报告「存入知识库」：存的是**用户勾选的来源**（每个来源独立一条文档），弹窗选库/分组/可见性/标签 → 创建文档（PENDING）→ 入审核队列。
- 管理端审核通过 → BullMQ 自动学习（连续流程动画：生成 → 保存至知识库 → 文档切片）。管理端雏形本期实现审核队列接口，管理页 UI 归 M6。
- `search.controller` 的 `save-kb` 桩替换为真实逻辑。

## 十一、风险与降级

| 风险 | 降级 |
| --- | --- |
| 无 ARK_API_KEY → embedding 不可用 | 跳过向量化，检索退 PG 全文；Key 配置后 `relearn` 补齐向量 |

| 文件解析二进制异常 | 文档置 FAILED + failReason，可重新学习 |
| 队列进程重启中断 | 文档状态 INTERRUPTED，可继续学习 |

## 十三、实现落点与变更记录

### M3.2（2026-08-27 完成，详细进度见 04-开发规划「M3.2 阶段记录」）

- **决策点已确认**：xlsx + mammoth + pdf-parse / 引入 BullMQ / 无 Key 退化纯全文。另支持 txt/md 直读。
- **原始文件落库**：`kb_documents` 增 `file_data bytea`（≤50MB，migration `kb_file_data`）。上传时字节随 multipart 进入队列载荷（Base64）并落库；重新/继续学习时回读——否则进程重启后中断文档无法续学，「配 Key 后 relearn 补向量」也不可行。Qdrant point id 直接取切片主键，payload 携带 `{tenantId, libraryId, documentId, groupId, index}`。
- **模块结构微调**（对照第二节）：切片器为纯函数 `chunk/chunker.ts`；embedding 独立为 `embeddings/embed.service.ts`（便于单测）；新增 `learning/learning.service.ts` 作为学习编排纯服务（队列 worker 与降级同步路径共用）；BullMQ 以裸客户端（Queue/Worker 动态 import）使用，未走 @nestjs/bullmq 装饰器注册——Queue 创建失败或 Worker 启动失败仅告警降级，不阻断应用启动。
- **状态机补充**：服务启动清扫遗留 LEARNING→INTERRUPTED（第五节中断语义的落地方式）；失败重试 attempts=3 指数退避由队列承担，最终失败置 FAILED。
- **检索退化链路验证**：无 ARK_API_KEY 时 embed.enabled=false → 切片 vector_id 为空、Qdrant 不建集合；M3.3 全文路即唯一生效路。

### M3.3（2026-08-27 完成，详细进度见 04-开发规划「M3.3 阶段记录」）

- **新增 `retriever/kb.retriever.service.ts`**：混合检索编排——向量路（embed 问题 → 遍历租户各库已有 collection 并发检索 → 库 threshold 过滤 → PG 回填切片内容与文档名）+ 全文路（查询分词 → PG ILIKE 多关键词匹配，`unnest($1::text[])` 单参数数组，按命中词数降序取前 50 行）→ 复用 `fusion/rrf.ts` 按库分组融合（组权重=库 `weight`）→ 截断 20 条 → 映射 SearchHit（title=文档名，snippet=前 160 字，contentMd=切片全文，meta={libraryId,groupId,documentId,idx}，rawScore=跨渠道最高相似度）。
- **打分语义（实现决策）**：向量相似度=Qdrant cosine（0~1 钳制），低于库 threshold 的向量命中检索期剔除；全文相似度=命中词数/提取词总数——ILIKE 子串匹配无真实语义距离，**不设库阈值过滤**（保证无 Key 退化模式下全文路可出结果），仅用于排序与分级展示。同一切片多渠道命中取最高相似度作为 rawScore。
- **分词（纯函数 `extractQueryTerms`）**：ASCII 小写词（≥2 字符）+ CJK bigram 滑窗（无词典分词折中），去重保序、上限 24 个；`toIlikePattern` 转义 `%_\`。伪链接 `kb://{libraryId}/{documentId}/{idx}` 作为本地命中唯一标识兼作外层融合去重键——同一文档多切片不塌缩。
- **LocalConnector 真实化**：注入 KbRetrieverService；失败显式 warn + 返回空（管道层 runConnector 吞错静默，连接器必须自带日志否则无从排查）。本地路超时 3s→8s（含问题向量化网络调用）。
- **三模式路由**：`SearchService.search` 增可选 `routes: ReadonlySet<SourceType>` 过滤连接器；controller 增 `ROUTES_BY_MODE`（hybrid=三路全开 / web=联网+垂直 / local=仅本地），`mode` 参数自此真正生效。
- **装配**：KbModule 导出 KbRetrieverService，SearchModule 引入 KbModule；qdrant 增 `listCollectionNames`；store 增 `listLibraryRetrievalConfigs`/`getChunksWithDocNames`/`searchChunksFulltext`（系统 client 显式 tenantId）。
- **kb:// 展示治理**：前端来源卡对 `kb://` 前缀不渲染链接（内部标识非真实地址）；generate 服务拼 prompt/降级摘要时不再携带该伪链接。
- **联调验证**：知识库模式仅出知识库命中；混合模式知识库命中排序第 0（本地优先加权生效）；联网模式零知识库命中。API 层与浏览器 UI 全链路均验证通过（开发期注意：Windows 控制台 GBK 传参会弄乱中文查询参数，浏览器/前端无此问题）。
