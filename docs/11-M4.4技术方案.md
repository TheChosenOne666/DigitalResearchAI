## 二、数据设计

### 2.1 新增表 `workspace_datasets`（我的数据 = 收藏的数据集快照）

```prisma
model WorkspaceDataset {
  id          String   @id @default(cuid()) @db.VarChar(32)
  tenantId    String   @map("tenant_id") @db.VarChar(32)
  userId      String   @map("user_id") @db.VarChar(32)
  name        String   @db.VarChar(255)
  data        Json                                  // 时序快照：indicator/countries/years/series/sources
  tags        Json?                                 // 标签数组
  status      String   @default("ACTIVE") @db.VarChar(16)   // ACTIVE / ARCHIVED
  sourceType  String   @map("source_type") @db.VarChar(16)  // WDI / upload / mixed
  createdAt   DateTime @default(now()) @map("created_at")
  updatedAt   DateTime @updatedAt @map("updated_at")

  @@index([tenantId, createdAt])
  @@map("workspace_datasets")
}
```

- `tenant-filter.ts` 的 `TENANT_MODELS` 增加 `'WorkspaceDataset'`。
- 无字段变更、无迁移破坏（纯新增表）。

### 2.2 复用既有表（无改动）

- `workspace_reports`：分析结果报告（M4.3 已建）。
- `search_reports` / `search_sources`：智搜报告与来源（M2 已建，`{c:N}` ↔ `search_sources.idx` 映射）。

## 三、接口设计

### 3.1 报告导出（新增 `report` 模块）

```
POST /report/export
  body: { type: 'search' | 'workspace', id: string, format: 'docx' | 'pptx' }
  返回: 二进制流（Content-Type + Content-Disposition 附件下载）
```

- `type=search`：`id` 为 **sessionId**，内部复用 `SearchStoreService.reportDetail(sessionId)` 取最新报告 + sources，正文 `{c:N}` → 上标 `[N]`，文末按 idx 升序生成「参考来源」表。
- `type=workspace`：`id` 为 **reportId**，复用 `WorkspaceStoreService.reportDetail(id)`，14 章节 + 数据分析表 + 数据来源表。
- 导出落审计（`auditLog.create`，action=`EXPORT`，targetType=`report`，detail 含 type/format）。
- 入参非法（type/format 未知、id 缺失）→ 400；跨租户/不存在 → 404。

### 3.2 我的数据（workspace 扩展）

```
GET    /workspace/datasets              列表：keyword/tag/status/page/pageSize → { list, total }
POST   /workspace/datasets              收藏快照：{ name, tags[], data, sourceType }
POST   /workspace/datasets/:id/archive  归档/恢复（toggle status）
DELETE /workspace/datasets/:id          删除（跨租户 → 404）
GET    /workspace/datasets/export       导出清单（CSV：名称/标签/状态/来源/更新时间）
```

- 快照 `data`：`{ indicator, countries, years, series, sources }`（前端工作台收藏时传当前筛选 + 合并时序）。
- 归档/恢复为幂等 toggle；删除为硬删（用户确认后）。
- `GET .../export` 返回 `text/csv` 附件。

### 3.3 我的报告（workspace 扩展，聚合）

```
GET /workspace/reports                 聚合列表：keyword/type/page/pageSize → { list, total }
GET /workspace/reports/:id/versions    版本列表：?type=search|workspace → { list }
```

聚合列表项（统一形状）：

```ts
{
  type: 'search' | 'workspace',   // search → sessionId；workspace → reportId
  id: string,
  name: string,                    // search → question 截断；workspace → title
  format: string,                  // '智搜报告' | '分析报告'
  version: number,                 // search → session 下报告数；workspace → version 字段
  updatedAt: string,
  status: string,                  // search → 'READY'；workspace → DRAFT/ARCHIVED
}
```

- 聚合实现：分别查两类（SearchSession 含最新 report + WorkspaceReport）→ 内存合并 → 按 updatedAt 降序 → 分页。
- 版本列表：`type=search` 查该 session 下全部 reports（按 createdAt 升序，序号即版本）；`type=workspace` 返回当前 report 单条（version 字段）。

## 八、风险

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| `docx`/`pptxgenjs` 与 pnpm/Node 22 兼容 | 中 | 先装后 build 验证；版本锁定主版本 |
| Markdown 解析器覆盖不全（LLM 输出结构漂移） | 中 | 只支持固定块级结构（标题/段落/列表/表格），其余降级为段落，不崩溃 |
| 聚合列表跨表分页 | 低 | 内存合并排序（两类数据量小），无 SQL union 复杂度 |
| 引文编号与 sources 序号错位 | 低 | 严格复用 `search_sources.idx`（与 `{c:N}` 同源），不另行编号 |
